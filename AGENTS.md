# AGENTS.md

## Conventions

- Code in English.
- Directory and file names in Spanish.
- UI in Spanish.
- README.md in Spanish.
- Keep the code simple to understand for programming Juniors.
- Apply SOLID principles.
- Reuse existing components and utilities when appropriate instead of duplicating logic.

### Git - GitHub

You must also manage Git commits and branches, and Pull Requests on GitHub.

#### Commits

- Write commit messages in English.
- Follow the Conventional Commits format: type(scope): description.
- Use concise, descriptive commit messages written in the imperative mood.
- Keep commits focused on a single logical change.
- Avoid committing unrelated changes together.
- Never commit generated files, temporary files, secrets, credentials, or sensitive information.
- Review the changes before committing to ensure only intended modifications are included.
- Keep modules cohesive and avoid circular dependencies.

#### Pull Request

- Use descriptive titles that summarize the purpose of the changes.
- Provide a clear description explaining what changed and why.
- Reference related issues when applicable.
- Keep pull requests focused and reasonably sized.
- Ensure relevant tests pass before submitting a pull request.
- Review the diff for unintended changes, debugging code, or sensitive information.
- Do not merge pull requests unless explicitly instructed.

#### Branches

- Use descriptive, lowercase branch names with hyphens separating words.
- Use appropriate prefixes to indicate the branch purpose:
  - feature/ for new features.
  - fix/ for bug fixes.
  - refactor/ for code restructuring.
  - docs/ for documentation changes.
  - test/ for test-related changes.
- Keep branches focused on a single task or objective.
- Avoid working directly on main unless explicitly instructed.
- Keep branches synchronized with their base branch when necessary.
- Delete branches after they have been successfully merged, when appropriate.

## Rules
